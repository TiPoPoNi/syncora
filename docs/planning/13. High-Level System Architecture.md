## High-Level System Architecture

The system will follow a **modular full-stack architecture** in which the frontend, backend, database, scheduling engine, and future AI layer have clearly separated responsibilities.

The architecture is designed so that the **core project-management and scheduling system works independently**, while advanced AI capabilities can be added later without rebuilding the entire application.

### 1. Overall Architecture

```
                         USERS
                           │
          ┌────────────────┼────────────────┐
          │                │                │
       Manager           Client          Worker/Vendor
          │                │                │
          └────────────────┼────────────────┘
                           ▼
                  ┌─────────────────┐
                  │   React Frontend│
                  │ TypeScript      │
                  │ Tailwind CSS    │
                  └────────┬────────┘
                           │
                        HTTPS
                           │
                           ▼
                  ┌─────────────────┐
                  │   REST API      │
                  │   Spring Boot   │
                  └────────┬────────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
   Authentication    Business Logic   Scheduling Engine
   & Authorization   & Services       & Algorithms
          │                │                │
          └────────────────┼────────────────┘
                           │
                           ▼
                  ┌─────────────────┐
                  │   PostgreSQL    │
                  │    Database     │
                  └─────────────────┘
```

### 2. Frontend Layer

The frontend will be built using:

**React + TypeScript + Tailwind CSS**

It will provide interfaces for:

- Login
- Dashboard
- Projects
- Tasks
- Clients
- Workers
- Vendors
- Resources
- Calendar
- Gantt chart
- Notifications
- Reports
- User profiles

The frontend will communicate with the backend exclusively through REST APIs.

### 3. Backend Layer

The backend will use:

**Java + Spring Boot**

The backend will be divided into logical modules:

```
Spring Boot
│
├── Authentication Module
├── User Module
├── Client Module
├── Project Module
├── Task Module
├── Worker Module
├── Vendor Module
├── Resource Module
├── Scheduling Module
├── Dependency Module
├── Notification Module
├── Reporting Module
└── Audit Module
```

This keeps the application organized while still allowing us to build it as a **modular monolith** rather than unnecessarily using microservices.

### 4. Authentication & Authorization

**Spring Security + JWT** will handle security.

The flow will be:

```
User Login
    ↓
Spring Security
    ↓
Validate Credentials
    ↓
Generate JWT
    ↓
Frontend Stores Token
    ↓
API Requests
    ↓
JWT Validation
    ↓
Role Verification
    ↓
Allow / Deny Request
```

For example, a Worker should not be able to access administrative project-management operations.

### 5. Business Logic Layer

The business layer will contain the actual rules of the application.

For example:

```
Can this worker be assigned?
        ↓
Is worker available?
        ↓
Does worker have required skill?
        ↓
Does assignment overlap?
        ↓
Does assignment violate project constraints?
        ↓
YES → Reject / warn
NO  → Allow assignment
```

This layer should contain business rules rather than putting them directly inside controllers.

### 6. Scheduling Engine

This will be one of the most important technical components.

It will process:

```
Tasks
   +
Dependencies
   +
Task Duration
   +
Resource Availability
   +
Priorities
   +
Project Deadline
        ↓
Scheduling Engine
        ↓
Project Schedule
```

The scheduling engine will use:

- Graph algorithms
- Topological sorting
- Priority queues
- Critical Path Method
- Resource availability analysis
- Conflict detection
- Delay propagation

### 7. Database Layer

**PostgreSQL** will store the persistent application data.

Conceptually:

```
Users
 │
 ├── Clients
 ├── Workers
 └── Vendors

Clients
 │
 └── Projects
       │
       ├── Tasks
       │     │
       │     └── Dependencies
       │
       ├── Resources
       │
       ├── Assignments
       │
       ├── Milestones
       │
       └── Schedules
```

The exact ER diagram will be designed in the **Database Design phase**, so we should not lock every table down yet.

### 8. Notification Layer

The backend will generate notifications when important events occur.

For example:

```
Vendor Delay
     ↓
Backend detects change
     ↓
Affected tasks identified
     ↓
Project risk recalculated
     ↓
Notification generated
     ↓
Manager Dashboard
```

For V1, we can use **in-app notifications**. Email/SMS can be added later.

### 9. Future AI Layer

The AI will be an additional intelligence layer rather than the foundation of the application.

```
              Core Application
                    │
                    ▼
             Scheduling Engine
                    │
                    ▼
              Project State
                    │
                    ▼
              ┌───────────┐
              │ AI Layer  │
              └─────┬─────┘
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    Risk        Resource     Schedule
  Analysis    Recommendation Optimization
```

The AI may eventually use:

**Python + FastAPI + ML/LLM components**

but we will introduce this only after the core system is working.

### 10. Deployment Architecture

For development and deployment:

```
                Docker Environment
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
   Frontend         Backend        PostgreSQL
   Container        Container       Container
       │               │               │
       └───────────────┼───────────────┘
                       │
                 Docker Compose
```

### Architectural Principle

The most important design principle is:

**Core System → Deterministic & Reliable**

**AI Layer → Optional Intelligence**

So even if the AI service is unavailable, the following must continue working:

- Projects
- Tasks
- Workers
- Vendors
- Resource allocation
- Dependencies
- Scheduling
- Deadlines
- CPM
- Conflict detection
- Reports

This makes the project much more robust and gives you a strong architectural story for your resume and viva.

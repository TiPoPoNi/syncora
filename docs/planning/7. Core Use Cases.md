## Core Use Cases

The **Project Resource Allocation & Scheduling System** will support the following major use cases.

### 1. User Authentication & Access

Users can:

- Register/login.
- Log out securely.
- Access features according to their role.
- Manage their profile.

**Actors:** Admin, Project Manager, Client, Worker, Vendor

### 2. Project Creation & Management

The Project Manager can:

- Create a new project.
- Assign a client.
- Set project start and end dates.
- Define project priority.
- Add project requirements.
- Create milestones.
- Track project progress.
- Update or close the project.

**Actors:** Project Manager, Client

### 3. Task Management

The Project Manager can:

- Create project tasks.
- Define task duration.
- Set priorities.
- Assign workers/vendors.
- Set start and deadline dates.
- Track task status.
- Update task progress.

**Actors:** Project Manager, Worker, Vendor

### 4. Resource Allocation

The Project Manager can:

- View available workers/resources.
- Check resource workload.
- Assign resources to tasks.
- Reassign resources.
- Monitor resource utilization.

The system should prevent or warn about overlapping resource assignments.

### 5. Vendor Management

The Project Manager can:

- Add vendors.
- Assign vendors to projects/tasks.
- Define vendor deliverables.
- Set delivery deadlines.
- Monitor vendor status.
- Track vendor delays and performance.

**Actor:** Vendor

### 6. Task Dependency Management

The Project Manager can define relationships such as:

```
Design
   ↓
Material Procurement
   ↓
Production
   ↓
Installation
```

The system should prevent invalid dependency structures and identify affected tasks when a dependency changes.

### 7. Schedule Generation

The system generates a project schedule using:

- Task duration
- Dependencies
- Resource availability
- Priorities
- Working periods
- Project deadline

The generated schedule can then be reviewed and modified by the Project Manager.

### 8. Resource Conflict Detection

The system checks whether a resource is already assigned during a required period.

Example:

```
Worker A
Project 1 → Oct 10–15

New Assignment
Project 2 → Oct 12–16
```

The system generates:

> **Resource Conflict: Worker A is already assigned during Oct 12–15.**

### 9. Deadline Monitoring

The system continuously tracks:

- Upcoming deadlines
- Overdue tasks
- Milestones
- Vendor deadlines
- Project deadlines

It can notify relevant users when important deadlines approach or are missed.

### 10. Delay Management

When a worker or vendor reports a delay, the Project Manager can record:

- Delay reason
- Delay duration
- Affected task
- Expected new completion date

The system then analyzes the possible impact on dependent tasks.

### 11. Delay Propagation Analysis

For example:

```
Vendor Delay
     ↓
Material Delivery
     ↓
Production
     ↓
Installation
     ↓
Final Delivery
```

The system identifies which downstream tasks may be affected and whether the final project deadline is at risk.

### 12. Critical Path Analysis

The system analyzes task dependencies and identifies the **Critical Path**.

It helps the Project Manager understand:

- Which tasks cannot be delayed.
- Which tasks have available slack.
- Which activities directly affect project completion.
- Minimum possible project duration.

### 13. Project Monitoring

The Project Manager can monitor:

- Overall progress
- Task completion
- Delayed tasks
- Resource utilization
- Upcoming deadlines
- Project risk
- Milestone status

### 14. Client Monitoring & Approval

Clients can:

- View project progress.
- View milestones.
- Review expected completion dates.
- Submit requirements.
- Approve milestones or deliverables.
- Receive project updates.

### 15. Worker Task Execution

Workers can:

- View assigned tasks.
- View deadlines.
- Update progress.
- Mark tasks as completed.
- Report problems.
- Report delays.
- View their schedules.

### 16. Vendor Delivery Management

Vendors can:

- View assigned deliveries.
- Confirm delivery dates.
- Update delivery status.
- Report delays.
- Submit required documents.

### 17. Notifications

The system can generate notifications for:

- New task assignment.
- Upcoming deadline.
- Overdue task.
- Resource conflict.
- Vendor delay.
- Project risk.
- Schedule modification.
- Client approval request.

### 18. Reports & Analytics

The system can generate reports covering:

- Project performance
- Resource utilization
- Worker workload
- Vendor performance
- Delays
- Deadline compliance
- Project completion

### 19. AI/Intelligent Recommendations — Future Phase

The advanced version can allow the system to:

- Recommend suitable workers.
- Predict project-delay risk.
- Recommend alternative vendors/resources.
- Suggest schedule changes.
- Analyze the impact of delays.
- Explain why a project is at risk.

The AI will initially **recommend actions rather than automatically execute them**. The Project Manager will remain responsible for approving important schedule or resource changes.

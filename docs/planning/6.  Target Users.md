## Target Users

The **Project Resource Allocation & Scheduling System** is designed primarily for organizations where projects require coordination between multiple people, teams, clients, vendors, and resources.

### 1. Project Manager

The **Project Manager** is the primary user of the system.

They can:

- Create and manage projects.
- Define project deadlines and milestones.
- Create and assign tasks.
- Allocate workers and vendors.
- Define task dependencies.
- Monitor project progress.
- View schedules and Gantt charts.
- Detect resource conflicts.
- Monitor delayed tasks.
- Analyze project risks.
- Review scheduling recommendations.
- Approve proposed schedule changes.

### 2. Administrator

The **Administrator** manages the overall platform.

They can:

- Manage users and roles.
- Add/remove workers and vendors.
- Manage system configurations.
- Monitor system activity.
- View audit logs.
- Manage access permissions.
- Monitor overall organizational projects and resources.

### 3. Client

The **Client** interacts with the system to monitor their projects.

They can:

- View assigned projects.
- View project progress.
- View important milestones.
- View expected completion dates.
- Submit requirements.
- Provide approvals.
- Track project status.
- Receive important project updates.

### 4. Worker / Employee

Workers are responsible for completing assigned project tasks.

They can:

- View assigned tasks.
- View task deadlines.
- View their schedules.
- Update task progress.
- Mark tasks as completed.
- Report delays or problems.
- View task dependencies.
- Update availability when applicable.

### 5. Vendor

Vendors provide materials, services, or external resources required by projects.

They can:

- View assigned work or deliveries.
- View expected delivery dates.
- Update delivery status.
- Report delays.
- Provide relevant information/documents.
- View their active project commitments.

### 6. Management / Business Owner — Optional

For larger organizations, a higher-level management role can be included.

They can:

- View organization-wide project performance.
- Monitor resource utilization.
- Compare project performance.
- Review delayed projects.
- Analyze vendor performance.
- View business-level reports and analytics.

### User Hierarchy

```
                    Administrator
                         │
              ┌──────────┴──────────┐
              │                     │
        Project Manager        Management
              │
      ┌───────┼────────┐
      │       │        │
    Client  Worker   Vendor
```

For the **first version**, we should focus on **five core roles**:

**Admin → Project Manager → Client → Worker → Vendor**

The **Management/Business Owner** role can be added later if the project requires organization-level analytics.

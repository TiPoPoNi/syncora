## Technology Stack

We will intentionally keep the technology stack **small, modern, and practical** so that the project remains easy to develop, maintain, deploy, and explain during your viva.

### Frontend

**React.js**

- Component-based UI
- Dashboard
- Project management
- Task management
- Resource management
- Gantt chart and calendar interfaces

**TypeScript**

- Type safety
- Better maintainability
- Safer API integration

**Tailwind CSS**

- Responsive UI
- Consistent styling
- Faster frontend development

### Backend

**Java**

- Core programming language
- Scheduling algorithms
- Resource allocation logic
- Dependency analysis
- Business logic

**Spring Boot**

- REST API development
- Backend architecture
- Service layer
- Database integration
- Validation
- Exception handling

**Spring Security**

- Authentication
- Authorization
- Role-Based Access Control

**JWT**

- Secure user authentication
- Stateless API sessions

### Database

**PostgreSQL**

PostgreSQL will be the **primary and only database in V1**.

It will store:

- Users
- Roles
- Clients
- Projects
- Tasks
- Workers
- Vendors
- Resources
- Dependencies
- Assignments
- Schedules
- Deadlines
- Notifications
- Audit logs

We don't need MongoDB for the initial version.

### Scheduling & Algorithms

The scheduling engine will be implemented directly in **Java**.

Important concepts:

- Graph data structures
- Directed Acyclic Graph (DAG)
- Topological Sorting
- Priority Queue
- Critical Path Method (CPM)
- Resource allocation
- Conflict detection
- Dependency analysis
- Delay propagation
- Schedule recalculation

This is one of the areas where your **DSA knowledge** directly contributes to the project.

### Visualization

For the project dashboard:

**Recharts**

- Project progress
- Resource utilization
- Worker workload
- Vendor performance
- Project-risk statistics

For scheduling:

**Gantt chart component/library**

- Task timeline
- Dependencies
- Milestones
- Progress
- Deadlines

We can select the exact Gantt library during implementation rather than locking ourselves into one now.

### API & Development Tools

**REST APIs**

- Frontend ↔ Backend communication

**Postman**

- API testing
- Authentication testing
- Endpoint testing

**Git + GitHub**

- Version control
- Branch management
- Collaboration
- Project history

### Deployment

**Docker**

- Containerize backend
- Containerize frontend
- Run PostgreSQL consistently
- Simplify deployment

**Docker Compose**

- Run the complete application stack together.

The basic deployment architecture will be:

```
┌─────────────────────┐
│      React          │
│   TypeScript + UI   │
└──────────┬──────────┘
           │
         REST
           │
           ▼
┌─────────────────────┐
│    Spring Boot      │
│       Java          │
│                     │
│ Business Logic      │
│ Scheduling Engine   │
│ Resource Allocation │
│ Authentication      │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│     PostgreSQL      │
└─────────────────────┘
```

### AI Layer — Later

We will **not add the AI stack during the initial development**.

When the core system is stable, we can introduce:

**Python + FastAPI**

for advanced intelligence such as:

- Delay prediction
- Resource recommendation
- Schedule optimization
- Project risk analysis

And an **LLM** can later be added for the project-management assistant.

The important principle is:

> **Core scheduling should work without AI. AI should enhance the system, not be required for the system to function.**

### Final V1 Stack

So the core stack is simply:

**Frontend:** React + TypeScript + Tailwind CSS  
**Backend:** Java + Spring Boot + Spring Security  
**Database:** PostgreSQL  
**Algorithms:** Java + DSA + CPM + Graph Algorithms  
**Visualization:** Recharts + Gantt Chart  
**Testing:** Postman + Unit/Integration Testing  
**Version Control:** Git + GitHub  
**Deployment:** Docker + Docker Compose

This is enough to build a **serious full-stack resume project** without creating unnecessary technology complexity.

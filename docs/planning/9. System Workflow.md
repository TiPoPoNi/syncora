## System Workflow

The **Project Resource Allocation & Scheduling System** will follow a structured workflow that connects clients, project managers, workers, vendors, resources, tasks, schedules, and deadlines.

### 1. Project Creation

The Project Manager creates a project by entering:

- Project name
- Client
- Description
- Start date
- Final deadline
- Priority
- Required resources
- Project requirements
- Milestones

The system creates the project and establishes its initial timeline.

### 2. Task Breakdown

The Project Manager divides the project into smaller tasks.

For each task, the system stores:

- Task name
- Description
- Estimated duration
- Priority
- Required skills/resources
- Start date
- Deadline
- Assigned worker/vendor
- Status

Example:

```
Project
   │
   ├── Design
   ├── Material Procurement
   ├── Production
   ├── Quality Check
   ├── Installation
   └── Final Delivery
```

### 3. Dependency Definition

The manager defines relationships between tasks.

For example:

```
Design
   ↓
Procurement
   ↓
Production
   ↓
Installation
   ↓
Final Delivery
```

The system understands that **Production cannot begin until Procurement is completed**, and Installation depends on Production.

### 4. Resource Allocation

The system checks available:

- Workers
- Vendors
- Equipment
- Other project resources

It considers their:

- Availability
- Skills
- Current workload
- Existing assignments
- Required task duration

The manager then assigns appropriate resources.

### 5. Schedule Generation

The scheduling engine processes:

```
Tasks
+
Dependencies
+
Resources
+
Availability
+
Priorities
+
Deadlines
```

and generates a feasible project schedule.

The system checks for conflicts before confirming the schedule.

### 6. Project Execution

Workers and vendors execute their assigned activities.

Workers can update:

- Task status
- Progress
- Completion
- Problems
- Delays

Vendors can update:

- Delivery status
- Expected delivery date
- Completion
- Delays

The Project Manager can monitor everything through the dashboard.

### 7. Continuous Monitoring

The system continuously evaluates:

- Task progress
- Deadlines
- Resource utilization
- Worker workload
- Vendor commitments
- Dependencies
- Project completion percentage

The dashboard provides a real-time view of the current project state.

### 8. Conflict Detection

Suppose Worker A is already assigned:

```
Project A
10 Oct → 15 Oct
```

and another task requires the same worker:

```
Project B
12 Oct → 16 Oct
```

The system detects the overlap and generates:

> **Resource Conflict: Worker A is unavailable from 12–15 October.**

The manager can then select another resource or modify the schedule.

### 9. Delay Detection

Suppose a vendor reports:

> Material delivery delayed by 3 days.

The system records the delay and checks the dependency graph.

```
Vendor Delay
     ↓
Material Delivery
     ↓
Production
     ↓
Quality Check
     ↓
Installation
     ↓
Final Delivery
```

### 10. Delay Impact Analysis

The system calculates which tasks are affected and determines the new expected project completion date.

For example:

```
Original Completion: 30 Oct
Vendor Delay:        +3 days
New Completion:       2 Nov
Client Deadline:     30 Oct

Result: 🔴 Deadline Risk
```

### 11. Critical Path Analysis

The system recalculates the project's critical path to determine whether the delay affects the activities that directly determine the final completion date.

If the critical path is affected, the project is flagged as high risk.

### 12. Schedule Adjustment

The manager can choose to:

- Reassign a worker.
- Change task priority.
- Reschedule a task.
- Add an available resource.
- Change a vendor.
- Run tasks in parallel where possible.

The scheduling engine recalculates the project timeline.

### 13. Manager Approval

The system can provide recommendations such as:

> **Recommended Action:** Assign Worker B to Installation.

The manager reviews the recommendation and approves or rejects it.

This keeps important business decisions under human control.

### 14. Project Completion

When all required tasks are completed:

```
All Tasks Completed
        ↓
Milestones Completed
        ↓
Final Deliverable
        ↓
Client Approval
        ↓
Project Completed
```

The system records the final completion date and project history.

## Functional Requirements

The **Functional Requirements** define what the Project Resource Allocation & Scheduling System must be able to do. These requirements describe the actual operations and behavior expected from the system.

### FR-01 — User Authentication

The system shall allow users to securely:

- Register where applicable.
- Log in and log out.
- Change their password.
- Manage their profile.
- Access the system according to their assigned role.

### FR-02 — Role-Based Access Control

The system shall support different user roles:

- Administrator
- Project Manager
- Client
- Worker
- Vendor

Each role shall have access only to the features and information permitted for that role.

### FR-03 — User Management

The Administrator shall be able to:

- Create users.
- Update users.
- Disable/enable accounts.
- Assign roles.
- View user information.

### FR-04 — Client Management

The Project Manager/Admin shall be able to:

- Create client profiles.
- Update client information.
- View client details.
- View projects associated with a client.
- Maintain client requirements and approvals.

### FR-05 — Project Management

The system shall allow authorized users to:

- Create projects.
- Edit projects.
- Assign clients.
- Assign project managers.
- Set project start and end dates.
- Set project priority.
- Define project milestones.
- Update project status.
- Track project progress.
- Close completed projects.

### FR-06 — Task Management

The Project Manager shall be able to:

- Create tasks.
- Edit tasks.
- Delete tasks where permitted.
- Assign tasks.
- Set task duration.
- Set task priority.
- Set deadlines.
- Track task status.
- Track task progress.
- Record task completion.

### FR-07 — Worker Management

The system shall maintain worker information including:

- Name/profile.
- Skills.
- Experience.
- Availability.
- Current assignments.
- Workload.
- Task history.

Project Managers shall be able to assign workers to suitable tasks.

### FR-08 — Vendor Management

The system shall allow authorized users to:

- Register vendors.
- Maintain vendor profiles.
- Define vendor services/materials.
- Assign vendors to projects/tasks.
- Set delivery commitments.
- Track vendor status.
- Record vendor delays.

### FR-09 — Resource Management

The system shall maintain the availability and utilization of project resources.

It shall allow managers to:

- View available resources.
- Assign resources.
- Reassign resources.
- Monitor workload.
- Identify over-allocation.
- Track resource utilization.

### FR-10 — Task Dependency Management

The system shall allow Project Managers to define dependencies between tasks.

For example:

```
Task A
  ↓
Task B
  ↓
Task C
```

The system shall ensure that dependent tasks are scheduled according to their dependencies.

It shall also detect invalid dependency structures such as circular dependencies.

### FR-11 — Schedule Generation

The system shall generate a project schedule using:

- Task duration.
- Task dependencies.
- Resource availability.
- Resource workload.
- Task priority.
- Project deadlines.

The generated schedule shall provide planned start and completion dates for project activities.

### FR-12 — Resource Conflict Detection

The system shall detect situations where:

- A worker is assigned to overlapping tasks.
- A resource exceeds its available capacity.
- A vendor has conflicting commitments.
- A required resource is unavailable.

The system shall notify the Project Manager about the conflict.

### FR-13 — Deadline Management

The system shall manage:

- Project deadlines.
- Task deadlines.
- Milestone deadlines.
- Vendor delivery deadlines.

The system shall identify upcoming and overdue deadlines.

### FR-14 — Delay Management

Authorized users shall be able to report delays by providing:

- Delayed task/resource.
- Delay reason.
- Delay duration.
- Expected new completion date.

The system shall store the delay as part of the project's history.

### FR-15 — Delay Propagation

When a task is delayed, the system shall analyze dependent tasks and determine whether the delay affects:

- Subsequent tasks.
- Resources.
- Milestones.
- Critical path.
- Overall project completion date.

### FR-16 — Critical Path Analysis

The system shall calculate the project's critical path using task dependencies and durations.

It shall identify:

- Critical tasks.
- Project minimum duration.
- Task slack/float.
- Activities that can directly affect the final deadline.

### FR-17 — Schedule Recalculation

When important project conditions change, such as:

- Task delay.
- Resource unavailability.
- Vendor delay.
- Deadline change.
- Task duration change.

the system shall be capable of recalculating the affected schedule.

### FR-18 — Project Dashboard

The system shall provide a dashboard containing information such as:

- Active projects.
- Completed projects.
- Delayed projects.
- At-risk projects.
- Upcoming deadlines.
- Overdue tasks.
- Resource utilization.
- Worker workload.
- Vendor performance.

### FR-19 — Gantt Chart & Calendar

The system shall provide visual scheduling interfaces showing:

- Tasks.
- Start/end dates.
- Dependencies.
- Milestones.
- Progress.
- Deadlines.
- Delays.
- Critical activities.

### FR-20 — Notifications

The system shall generate notifications for important events such as:

- Task assignment.
- Upcoming deadlines.
- Overdue tasks.
- Resource conflicts.
- Vendor delays.
- Project risks.
- Schedule changes.
- Approval requests.

### FR-21 — Client Access

Clients shall be able to:

- View their projects.
- View project progress.
- View milestones.
- View expected completion dates.
- Submit requirements.
- Provide approvals.
- Receive relevant notifications.

### FR-22 — Worker Access

Workers shall be able to:

- View assigned tasks.
- View deadlines.
- View schedules.
- Update task progress.
- Mark tasks completed.
- Report delays/problems.

### FR-23 — Vendor Access

Vendors shall be able to:

- View assigned projects/tasks.
- View delivery requirements.
- Update delivery status.
- Confirm delivery dates.
- Report delays.

### FR-24 — Reports & Analytics

The system shall generate reports for:

- Project performance.
- Resource utilization.
- Worker workload.
- Vendor performance.
- Delays.
- Deadline compliance.
- Project completion.

### FR-25 — Activity & Audit Logging

The system shall record important system activities, including:

```
User
Action
Timestamp
Affected Project/Task
Previous State
New State
```

This will allow managers and administrators to trace important changes.

### FR-26 — Approval Workflow

The system shall support approval processes for:

- Client requirements.
- Milestones.
- Deliverables.
- Schedule changes.
- Project completion.

### FR-27 — Intelligent Recommendations — Future Phase

The system may later provide:

- Resource recommendations.
- Schedule recommendations.
- Delay-risk analysis.
- Alternative resource suggestions.
- Schedule optimization.

AI-generated recommendations shall require appropriate human review before critical changes are applied.

### FR-28 — Data Search & Filtering

Authorized users shall be able to search and filter:

- Projects.
- Tasks.
- Clients.
- Workers.
- Vendors.
- Resources.

Filters may include status, priority, deadline, availability, and project.

### FR-29 — Data Export

The system may allow authorized users to export selected reports and project information in formats such as CSV or PDF.

### FR-30 — Project Completion

The system shall allow a project to be marked as completed only when the required tasks and milestones have been completed or appropriately approved.

The system shall preserve the project's final status, schedule, resource assignments, completion date, and activity history for future reference.
